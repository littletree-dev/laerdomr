# 失敗の型

Claude Code の個人運用で記録された161件（2026年08〜09月）から、環境を変えても起きる失敗を10型にまとめた下書きです。個人の事情・発言・資料名は一般化しています。F番号は元の記録との対応用で、元資料はこの集に含めません。

## 型の一覧

1. [一次資料を開かずに「無い」と決める](01-primary-evidence.md) — 検索範囲・形式・文脈の欠落を、事実の不在に置き換える。
2. [終了コードだけで成否を決めて空振りを見逃す](02-silent-failure.md) — 実行結果と成果物を別々に確認する。
3. [痕跡があるだけで機能が動いていると決める](03-traces-and-state.md) — 存在・登録・有効・稼働を区別する。
4. [文字を層の間で渡すうちに意味を壊す](04-text-boundaries.md) — 文字コード・引用・改行の変化を入口と出口で検出する。
5. [直しただけで受け手に届いたと決める](05-delivery-verification.md) — 文面の修正と実経路での到達を別に測る。
6. [測る前に説明を作って原因を決める](06-measure-first.md) — 変更前の証拠を保存し、仮説を分ける測定を先に置く。
7. [引き継ぎの数字を照合せず設計の前提にする](07-handoff-evidence.md) — 件数の差と内容の差を区別する。
8. [別の対象を検査して合格を報告する](08-test-the-claim.md) — 実入力と判定対象を結び付け、失敗する側も試す。
9. [自分で調べられる事実を利用者に聞く](09-check-before-asking.md) — 質問の前に取得済みの証拠と読取手段を突き合わせる。
10. [再発防止を注意書きで終える](10-enforce-prevention.md) — 同じ誤りを止める道具・検査・既定値まで作る。

## 読み方

症状から該当する型を開き、「仕組みでの対策」を作業経路に組み込んでください。「CLAUDE.md に書くなら」は貼り付け用の短い規則ですが、貼るだけで対策が実装されるわけではありません。対策はこの下書きでの提案であり、あなたの環境に導入済みという意味ではありません。

番号は、各束の代表的な核が元の集計で引用された回数を優先しています。順に F-46＝11回、F-8＝10回、F-18＝10回、F-11＝8回、F-24＝7回、F-87＝7回、F-94＝5回、F-99＝5回、F-20＝5回です。最後は対策を書くための横断的な型です。束の回数は合算していません。同じF番号が複数の型に登場することがあります。

引用回数は記録内で明示的に参照された回数です。発生件数・発生率・重大度や、現在も未解決であることを示す指標ではありません。

実例は当時の観測です。製品の現行仕様を保証しません。特に hook の失敗時の挙動、出力上限、PowerShell の文字コードは実行環境で検証してください。個人環境の設定値を共通の既定値として採用しないでください。

検証は隔離した作業用ディレクトリと合成データで行います。本番のデータ変更や外部送信を伴う試験は、その作業に必要な権限と承認の範囲で行ってください。
